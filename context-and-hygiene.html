Context & agent hygiene

Set up the folder system your agent reads, and the loop that keeps it updated.

An agent without context is a stranger every time you open a new chat. The fix isn’t a longer prompt — it’s a vault: a folder on your machine your agent reads every session. Identity in one place, working memory in another, reusable procedures in another. Below is the architecture and what each folder is for.

What each folder gives your agent

CLAUDE.md (root)

The first thing your agent reads every session. Tells it the name of the agent, the vault layout, and the operating rules (skills first, daily log every session, nothing gets deleted).

Why it matters: without this, the agent is a blank-slate stranger every time. With it, your agent walks into the room already knowing where it is.

agent/ — identity

Three short files that define who the agent is — pulled in via @-imports inside CLAUDE.md.

  • Soul.md — voice register, loyalty, the bond. The values layer.
  • Mind.md — canonical reasoning moves. How to push back, when to ask vs. assume.
  • Identity.md — name, pronouns, visual identity. The outward-facing shell.

Why it matters: personality and behavior stop being something you re-prompt every session. They’re durable. The agent disagrees with you the same way on Tuesday as it did on Monday.

Memory/Hippocampus.md — working memory

Two sections: Now (this week — what’s active, what’s on the calendar today, open threads) and Arc (longer horizon — who you are, where you’re going). Always loaded.

Why it matters: this is what makes the agent feel continuous. It opens the file and immediately knows what you’re in the middle of.

Memory/Daily/ — raw capture

One file per day, multiple sessions separated by ---. Written automatically by the Stop hook (in agent/scripts/) at the end of every session. Raw, ugly, unfiltered.

Why it matters: the input surface. You don’t have to remember to journal — the agent journals for you, and the nightly cycle distills the signal out.

Memory/People/

One markdown file per person who matters — family, colleagues, classmates, friends. Last interaction, ongoing threads, what they care about, links to relevant emails/messages.

Why it matters: the agent stops asking “who’s that?’’ You can say “draft a check-in to Mara” and it has the context to make it sound like you.

Memory/Lessons/ & Memory/Preferences/

Operational learnings (“don’t use mocks for integration tests — we got burned”) and working-style notes (“mornings = deep work, no meetings before 10”). Written by the extraction subagent when patterns recur.

Why it matters: mistakes compound into wisdom instead of evaporating. You don’t correct the agent on the same thing twice.

Memory/Weekly/, Meetings/, Connectors/

Weekly syntheses (Friday wrap-ups), meeting transcripts (Granola), and one note per data source you’ve wired up (Gmail, Calendar, Notion, Canvas) with its current status — so the agent knows what it can and can’t reach.

Why it matters: the agent knows where its eyes are. “Check my calendar” works because there’s a Connectors/ note that says yes, Gmail Calendar is wired, here’s the account.

Skills/ — reusable procedures

Each subfolder is one named procedure (plan-my-day/, send-email/, session-handoff/) with a SKILL.md describing pre-checks, work, evals, and definition-of-done. They register as slash commands — type /plan-my-day and the agent runs the procedure exactly the same way every time.

Why it matters: the difference between a chatbot and an agent. When something is worth doing twice, it becomes a skill. Reliability over cleverness.

.claude/ & .codex/ — hooks

The Stop hook appends every session to Memory/Daily/. The UserPromptSubmit hook (optional, wired later) does vector recall on your prompt and pulls relevant chunks of the vault back into context.

Why it matters: the loop closes itself. You don’t have to remember to save; the system remembers for you.

_seed/ — personalization input

Drop a folder here with your answers (answers.yaml, an essay, voice samples) and the /hatch skill reads it once to personalize the templates — substituting {{agent_name}}, {{user_name}}, voice register, domain folders. Then it gets archived.

Why it matters: the boring “set up my agent’s personality” step happens once, deterministically, from a structured input — not through 40 messages of back-and-forth.

The hygiene loop

Three loops keep the system from rotting:

  1. Every session — Stop hook writes raw capture to Memory/Daily/.
  2. Every night — /rem-cycle extracts signal from daily notes into People/, Lessons/, Preferences/, and refreshes Hippocampus.md’s Now.
  3. Every ~48 hours — the Arc section of Hippocampus gets refreshed from longer-horizon signal.

You don’t maintain it. The system maintains itself, and you correct it when it’s wrong.
